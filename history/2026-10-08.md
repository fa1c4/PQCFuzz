## Seven-module architecture implementation and demo

### Intent and design

Implemented the seven authoritative linked module contracts in `designs/` and removed the eight retired module documents. `designs/architecture.md` remains the authority. The new package protocol follows DES-01 through DES-10, with `oracles/<target>/` as the canonical new-target package and `src/runtime/` owning dynamic execution.

### Code and compatibility

Added `src/runtime/target_package.py` and `target_worker.py`, a thin `scripts/pqcfuzz_target.py` entry, a `targets` branch in `scripts/pqcfuzz_all_eval.sh` and a demo target wrapper. Registration checks schema, IDs, source/spec/package hashes, active knowledge, capability/primitive scope, budget and exact API/profile selection. A run copies source and target package into a unique workspace directory, snapshots spec/config/knowledge, executes a healthy/negative/fault smoke gate, then uses the paired structured mutator and oracle. Reports contain candidate-only counts; manifests carry draft evidence, hashes, environment/seed/budgets and `replay_status: not_run`.

The preexisting fixed suites still call historical jobs, fuzzers, replay, triage and reporting code. Reference search found these directories live; deleting them would break compatibility. No unrelated preexisting edits were reverted.

### Demo and checks

The public, non-PQC `demo-stream-hash` fixture uses H07/P4 and a local Section 1 streaming relation. `python -m unittest discover -s tests -p pqcfuzz_target_runtime_test.py -v` passed 6 tests: healthy and injected campaigns, fault/negative controls, verified status parsing, unknown oracle/schema, missing capability and out-of-scope primitive. A 6-iteration healthy run passed 6; injected run recorded 2 counterexample candidates. `bash scripts/pqcfuzz_all_eval.sh targets run --iterations 2` selected both registered profiles dynamically: healthy 2 passes; injected 1 pass/1 candidate. Single-target wrapper and legacy `--help` were checked. `git diff --check` returned no whitespace errors.

### Dependencies and limits

This Windows environment has Python 3.10 and Git Bash. `python -m pytest --version` fails with `No module named pytest`; no `clang++`, `g++`, `cl` or `cmake` is on PATH. Native C++ compatibility tests and a real PQC target build were therefore not executed. The new runtime uses only Python standard library. It currently blocks sensitive-input profiles and finite CPU/memory limits on Windows; its run-scoped subprocesses are not a security boundary against hostile source code. Retention expiry is recorded, with audited deletion deferred. The demo proves the infrastructure path, not 119-target coverage or a cryptographic security claim.


The `verify --run` entry checks the manifest digest, exact file set and all stored file hashes; a 27-file injected run verified successfully.

The final candidate report now embeds claim text, source locator, limitations, active property/pattern IDs and trace links. Preflight checks the original spec digest and unique claim IDs; each run snapshots the original document and records dependency version probes.
