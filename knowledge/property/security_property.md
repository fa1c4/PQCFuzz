# Active security properties

Catalog version: 1. Imported 2026-10-08 from E:/PQCFuzz/SecurityProperty/security_property.md (2026-09-23), SHA-256 4A2A3A2D3CC9BCE6DED6A569B1C79E083D9D330BA885E6AC920B1F9DEA70C153. Source sections are shown per entry below. The source is a secondary property inventory; each target-specific normative oracle must cite its own applicable specification/API contract. All entries below are version 1 and have fixed, never-reused IDs.

"Active" means available for property mapping, not automatically executable or proven. A game-level property needs a valid attacker model and concrete witness; finite fuzzing cannot prove IND-CCA, unforgeability, pseudorandomness or quantum resistance. Registration still requires an active pattern, target-specific relation, capabilities, controls and smoke gate. P01–P07 in the source are aliases for K01/K02/S01/S02/H01/H02/H03, not duplicate entries.

## Non-transfer rules from the source inventory

- ML-KEM's internal K-PKE is not a standalone PKE claim; distinguish public length errors from correctly sized invalid-ciphertext fallback.
- The source identifies ML-DSA with an sUF-CMA goal and SLH-DSA categories in EUF-CMA terms; apply each goal only after checking the exact target specification and API profile.
- Stateful LMS/XMSS-style index uniqueness does not apply to stateless SLH-DSA.
- The source's Aigis notes are snapshot observations and potential regression ideas, not NIST FIPS requirements or confirmed findings.
- Protocol authentication, forward secrecy and hybrid-combiner claims require a protocol/construction specification; they cannot be inferred from primitive correctness.
